# sentiment-b r1 generation review

## Handoff

- **200 new train + 40 new validation rows**, one independently authored event per group; no parent rows counted.
- Exact assigned domains and ranges: 20 train domains × 10 events (`g001`–`g200`); four validation domains × 10 events (`g201`–`g240`). Full namespace: `data:pilot-v2:sentiment-b:`.
- `group_assignments.json` was written before `source_cases.txt`; assignments and splits were not changed afterwards. `plan_groups.py` preserves the pre-authoring allocation and refuses to overwrite it.
- Authoring source: `source_cases.txt`; deterministic assembler/structural validator: `generate.py`. Reproduction uses `PI_PROVIDER=openai`, `PI_MODEL=gpt-sol`, Python standard library, and seed **670129**. These environment values are the observed teacher identity, not an invented immutable revision.
- Deliverables: `train.jsonl`, `validation.jsonl`, `metadata.json`, `validation_report.json`, this review, source cases, assignment JSON, and two private scripts. File hashes are in metadata/report; no shared manifest was created or edited.

## Content review

All 240 cases were authored for their frozen scenario plans, not generated by substituting a service into one review template. Within a domain, cases concern independent incidents: for example, cooking instruction covers hand movement, an allergen error, scheduling, fermentation, caramel, workstation allocation, pacing, sauce recovery, and hob access. The text does not refer back to another row.

Labels distinguish evaluation of the named subject from background facts. Successful adaptations, restrained interventions, and expectation reversals provide behavioural approval; usability failures and violated instructions provide criticism. Two-direction evaluations include an actual benefit and an actual defect, not merely two factual attributes. Non-evaluative cases report inventories, technical settings, appointment changes, and other facts without praising their correctness or criticising them. Every question names its subject, regardless of class. No state contains the prohibited answer-label words.

An author self-review removed incidental dashboard praise from the scratch-damage case before final assembly, keeping that case criticism-only. This review is **not independent verification of teacher labels**.

## Structural and shortcut checks

- Teacher-only provenance on every row; exact schema, family, split, singleton `:r01` IDs, opaque unique option IDs, and one supplied target verified.
- No duplicate IDs, duplicate canonical states, duplicate canonical full inputs, or cross-split groups within this shard.
- Exactly **50 rows per class in train**, **10 per class in validation**. All four mutually exclusive descriptions appear in every row.
- Target-position totals: **50/50/50/50 train**, **10/10/10/10 validation**. Within each class, positions differ by at most one, with excess positions rotated across classes.
- Five complete candidate phrasing styles and five question forms each appear equally often within each class/split: 10 per class/style in train, two in validation. Styles, questions, positions, distractor order, and output row order use independent deterministic random schedules.
- All four options within each row have the same whitespace-word length; zero uniquely-longest correct options. This removes a word-length ranking cue, not every possible character/subword cue.
- States: **20–30 words**; questions: at most **10 words**; options: at most **10 words**. No tokenizer was used; the parent's 256-token audit remains pending.

## Split-boundary review

The generator reads only files in this private directory and does not inspect historical or evaluation examples. Domain allocation came from the supplied config, including reserved validation boundaries. No external data, network access, model loads, tests, linting, paid generation calls, or Git operations were used.

CPU lexical review compared this shard's train states with its own validation states only. The maximum word-set Jaccard score was **0.23077**. All eight reported pairs were reviewed: they share generic booking, inventory, address-update, or collection vocabulary rather than a common authored incident. The highest pair (`g083`/`g233`) concerns a car-wash lane booking versus a darkroom enlarger booking; the next (`g113`/`g213`) concerns art-lesson file formats versus a loom-rental equipment agreement. The vehicle-trim care / wind-adjusted bird-flight pair (`g085`/`g225`) shares a broad care/adaptation theme but no event, actor, or object. None was moved across splits.

Historical corpus deduplication was not possible under the no-inspection boundary. Independent teacher spot review and the parent tokenizer audit are still required. Factual rows intentionally share some ordinary logistics vocabulary; this is not a claim of lexical disjointness.
