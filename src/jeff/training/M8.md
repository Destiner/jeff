# M8 producer and provisional P6 proof interface

Implementation only until the owner reviews/freezes this source and agrees the
exact proof fields with Runtime. No execution result or compatibility claim is
implied. M6/M7 commands and v1 manifests remain unchanged. M8 has its own CLI;
there is deliberately no capacity, resume, retry, or update-count option.

## Owner commands (separate fresh supervised processes)

Use the existing isolated locked model environment; do not alter dependencies.
Set the original offline/backend environment consistently with M7. Every output
directory must be new and absolute. The owner supplies a distinct supervisor
attestation for each child process and enforces its deadline externally:

```sh
uv run --locked --extra model python -B -m jeff.training.qwen_readout audit \
  --supervisor-receipt /absolute/audit-supervisor.json \
  --output-dir /absolute/NEW/train-audit
uv run --locked --extra model python -B -m jeff.training.qwen_readout train \
  --supervisor-receipt /absolute/train-supervisor.json \
  --audit-dir /absolute/NEW/train-audit \
  --authorize-run M8-ONE-original-P3-frozen-six-row-1500-375-seed42 \
  --comparison-freeze-sha256 OWNER_FROZEN_SHA256 \
  --output-dir /absolute/NEW/training
```

Supervisor attestation schema (small JSON written by the actual enforcing
supervisor before spawning; its recorded PID must be live and not the child):

```json
{
  "schema_version": "m8.supervisor.v1",
  "external_enforcement": true,
  "automatic_retry": false,
  "fresh_process": true,
  "supervisor_pid": 12345,
  "command": "train",
  "output_dir": "/absolute/NEW/training",
  "remaining_aggregate_seconds": 2500,
  "process_max_seconds": 2500
}
```

Values above are illustrative, not a launch grant. The owner must compute the
**remaining** aggregate allowance, counting audit and every zero-update plumbing
attempt. PID must refer to the actual enforcing supervisor; uv may be an
intermediate parent. A live PID and JSON attestation are not an OS sandbox or
proof of external enforcement. The enforcing parent must retain the actual command,
exit/timeout, wall time, source identity and no-retry process receipt. Cooperative
checks cannot interrupt blocked native operations. Keep external supervision
active through metadata publication/process exit. Guards cover lifetime CPU RSS
and sampled MPS driver <=16 GiB, recommended headroom >=2 GiB, and total process
<=min(2700, remaining allowance); CPU/MPS are overlapping scopes, not additive or
true peaks. No extra forward, capacity update, or training probe is authorized.

The audit loads only the tokenizer and rederives exactly the historical M6/M7
schedule, including actual token IDs, options and target identities. TRAIN only;
no D7, validation, final, control inference, or new canary. The parent separately
owns retained 624-control binding and schedules through P6's return. Training
revalidates clean committed executable/config/data/assets/environment pins in a
fresh process and consumes the byte-identical audited schedule without another
shuffle/tokenizer replay. All Python source, packaging/lock files and M8/P3 configs
are scientific pins; other tracked documents/files and the Git revision are
recorded context, not equality gates. M6/M7 binding behavior is unchanged. It loads
only original pinned P3, never M6/M7 learned weights. M6 capacity
reuse retains its actual historical successful receipt/source/shape checks while
explicitly **not** claiming M8's scope, optimizer geometry, export peaks, or the
historical full-parameter time projection have been established for M8.

## Failure and publication semantics

`failure-receipt.json` is an immutable **start sentinel**, not evidence of a
completed zero-update attempt. `status.json` is atomically replaced and fsynced
before **every optimizer step ATTEMPT**. A partial/failed first optimizer call
therefore cannot be interpreted as permission to repeat learning. Consult
`optimizer_step_attempts`, completed `optimizer_steps`, flushed events, and the
external process receipt. No retries after an attempt, no numerical/scope-binding
repairs, and no tolerance relaxation are implemented. Failure receipts are actual
`receipt.json` / `audit.json` with `status: failed` when Python can finalize;
SIGKILL leaves the sentinel/status/events. No completed manifest is published for
a failed producer.

After update375, `learned-head.safetensors` plus `head-evidence.json` are saved
**before** frozen/export/FINAL checks. Post-attempt exceptions also try to save
`learned-head-emergency.safetensors` and emergency movement evidence. Near-null
movement is valid; no hash-change or minimum-movement success threshold exists.
The full checkpoint, proof, completed source receipt and final manifest are
written in that order, without circular hashes. The manifest is staged then
published last after metadata guards, event closure, file permission sealing and
prepared-status output. The run directory remains writable for failure-receipt
replacement; checkpoint directories and completed files are sealed. A failed final
publication rewrites the actual receipt as failed; a pending manifest is never an accepted handoff. The
external supervisor must also report success before any handoff is consumed.
P6 owns the **sole** fresh load and 624+3 forwards. Producer only inspects saved
config and safetensors header keys/shapes/dtypes, not freshly loaded tensors.

## Canonical read-only helper

`jeff.model.qwen_readout_proof` has no torch/transformers import or ML side effect
at import. APIs accept already-loaded tensors/model and optional `guard(stage)`:

- `export_config(original)` -> exact permitted saved HF config: remove original
  `torch_dtype`; set `dtype=float32`, installed version4.57.6, cache false, tie false,
  sliding_window null, rope_scaling null and24full_attention layer types. Every
  other original field and the entire resulting key set must match.
- `tensor_record(tensor, guard=None)` -> `{shape, dtype: "float32", sha256, bytes}`.
- `backbone_records(model, guard=None)` -> `{parameters, fixed_buffers}`. Full
  `model.*` named-parameter keys, excluding `lm_head`; full `model.*` named-buffer
  keys separately, **including nonpersistent buffers**. Requires494032768
  original parameter scalars. Runtime compares its returned map to every producer
  before/after/export map, not just the embedding or a bounded fingerprint.
- `output_records(table, answer_token_ids, guard=None)` -> `{full_head,
  ordered_answer_rows, answer_rows: {decimal_token_id: tensor_record}, nonanswer_rows}`.
  `ordered_answer_rows` is the small `[6,896]` record in pinned A-F order.
- `nonanswer_record(table, answer_token_ids, guard=None)` hashes rows in ascending
  token-ID order excluding exactly the six answers, shape `[151930,896]`.
- `storage_disjoint(a,b)` validates FP32, CPU/MPS device, contiguous nonempty
  layout, nonzero storage token and offset/extent. CPU checks full storage byte
  intervals. MPS compares distinct backing MTLBuffer handles: these are opaque
  allocation identities, NOT payload addresses to which byte sizes can be added.
  The check covers our live allocator-owned `.to(MPS)`/clone tensors, not arbitrary
  externally aliased Metal buffers; the same backing buffer is rejected even for
  disjoint views. Cross-device storage is disjoint; Runtime additionally requires
  the expected same device/shapes. This source correction precedes any model load.

Canonical hashes cover only contiguous C-order **little-endian CPU float32
bytes**, not names/devices/JSON. Helpers require actual float32/contiguous tensors
and stream <=1Mi elements per CPU transfer; non-answer hashing uses contiguous
row ranges, never a giant gathered temporary. No device or model mutation.
