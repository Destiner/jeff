Temporary letters identify positions, not original option IDs. There was no prompt sweep, temperature fitting or outcome-driven change.

For **every** actual input and answer symbol, the audit tokenizes the entire rendered prompt plus symbol, verifies an unchanged prompt-token prefix, then requires exactly one distinct added token. Used letters A–F map to tokens 32–37 at this actual assistant boundary. Unsupported multi-token/boundary-changing continuations fail; no arbitrary first-token approximation is permitted.

The adapter reads the final prompt-position logits and computes `softmax(logits[allowed_symbol_tokens])` at temperature 1. These are probabilities **conditional on the next token being one of the supplied symbols**, not full-vocabulary confidence, probability of a complete generated answer, or calibrated confidence. No probability JSON is generated by the decoder. Transformers' native `logits_to_keep=1` slices hidden states before vocabulary projection; it does not allocate logits for every prompt token.

## Running this experimental path again

The audit/predict pair intentionally binds Git revision/status as well as file/config/input/tokenizer/environment hashes; a later code/doc commit requires a new audit before any new predictions.

```sh
uv sync --locked --extra model
# MODEL contains the already downloaded, pinned safetensors/tokenizer assets.
# INPUTS follows p3.inputs.v1 with the three E5 suites and explicit hashes/counts.
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  uv run --locked --extra model python -m jeff.runtime.qwen_challenger audit \
  --config configs/runtime/p3-qwen.json --inputs "$INPUTS" \
```
